# 验证脚本

这里放的是**可复现**的验证：不启动 ROS、不连 Gazebo、不需要 API Key，
任何人在任何机器上都能跑出同样结果。

## 怎么跑

```bash
cd portfolio/verification
python3 run_checks.py
```

输出会同时存档到 `results/`：

```
results/test_task_pipeline.txt
results/test_geometry.txt
results/summary.txt
```

## 覆盖什么

### `test_task_pipeline.py`：任务解析链路

| 编号 | 校验点 | 说明 |
|---|---|---|
| 1 | 种子 / 分隔线剥离 | 输入含 `使用种子: 997072` 和 `-----` 时，正文不被污染 |
| 2 | 题目 / 映射规则分离 | 规则从"编号 + 引号 + 无前缀"的写法里也能正确切出 |
| 3 | 三种官方规则提取 | 规则 1/2/3 的文本原样还原 |
| 4 | 任务题 vs 简单指令 | 出题输入判为任务题；"将红方块1送到A区域"不误判 |
| 5 | 方案解析鲁棒性 | 模型回复里混入示例 `[red,2,C;blue,3,A]` 时，仍取最后一个真实答案 |
| 6 | `/mission/task` 格式 | 四行：种子 / 题目 / 映射规则 / 方案 |
| 7 | 投放点居中 | `DROP_OFFSET == (0, 0)` |

被测对象：`arm_llm/arm_llm/deepseek_all_controller.py` 中的纯函数。
ROS 模块用最小桩替换（只保证可导入，不模拟行为）。

### `test_geometry.py`：场景几何

| 编号 | 校验点 | 当前结果 |
|---|---|---|
| 1 | 方块两两间距 ≥ 2.0 m | 45/45 通过，最小 **2.454 m** |
| 2 | 坐标落在地图覆盖范围内 | 10 方块 + 3 区域全部在内 |
| 3 | 放置区底板尺寸与碰撞 | 底板 1.0 × 0.5 × 0.02 m，collision 数量 0 |

第 3 项解释了一个已知现象：底板没有碰撞体，所以方块落地会陷进 2 cm。

## 这些测试**不**覆盖什么

诚实说明边界，避免过度解读：

- **不验证端到端成功率**：不启动 Gazebo/Nav2，因此不测试"机器人是否真的搬成功"；
- **不验证机械臂 IK 精度**：IK 与轨迹执行依赖真实 URDF 与控制器；
- **不验证大模型输出质量**：需要 API Key 与网络，且输出非确定。

端到端效果请参见 [media/README.md](../media/README.md) 里要求的录屏素材。

## 为什么放这些测试

求职材料里"我实现了 X"很难自证，而"这里有一个脚本，你可以自己跑，输出是这样"
是可验证的。这些测试同时也是我开发时的回归手段：

- 改提示词后回归解析逻辑；
- 换场景后立刻发现坐标 / 间距 / 地图越界问题；
- 把"已知限制"写进断言，避免以后被误当成 bug 反复排查。
